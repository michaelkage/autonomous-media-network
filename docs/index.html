Media Network.

A file-based media intake line. Fetch, inspect, reject, watermark, record—and optionally hand approved assets to a publisher. The manifest is the hand-off contract.

● Source-verified product scope

This repository automates a narrow, auditable workflow. It does not generate original media, understand image semantics, or autonomously decide what is culturally safe to post.

    02 — ARCHITECTURE

    The pipeline is a local filesystem workflow. Each image is paired with a JSON sidecar; the run drains the inbox by routing each candidate to output or rejection.

    01 / INTAKEinbox/Image + same-stem .json metrics
    02 / DECIDEVetting + dHashHard rules and near-duplicate check
    03 / PROCESSWatermarkAccepted image exported as JPEG
    04 / ROUTEoutbox / rejectedRejected files retain sidecars
    05 / HAND-OFFmanifest.jsonPublisher reads passing records
    Accepted

    outbox/

    Watermarked JPEG output. Original inbox image and sidecar are removed after successful processing.

    Rejected

    rejected/

    Rejected image and sidecar are moved together. Reasons are recorded in the manifest.

    State

    build/hashes.json

    Persistent list of 64-bit dHashes used to prevent near-identical images from being accepted again.

    Audit

    build/manifest.json

    Timestamp, counts, accepted provenance and digest, rejected reasons, and processing errors.

    Important ordering detail: duplicate detection runs before the metrics and quality vetting. A duplicate is rejected with its own reason, and it is not re-recorded as a new hash.

    The acceptance contract.

    03 — HARD GATES

    There is no warning-only path. A candidate must pass every applicable rule. The values below are the defaults shipped in pyproject.toml, not universal platform recommendations.

    RuleDefaultBehaviour
    min_width1080 pxReject if width is below the configured minimum.
    min_height1080 pxReject if height is below the configured minimum. Both dimensions must clear their floor.
    min_likes500Absolute likes/upvotes floor applied to every source.
    min_engagement_rate2.0%(likes + comments + shares) ÷ views. Checked only when views is positive and reported.
    allowed_formatsJPEG, PNG, WEBPFormat is taken from Pillow's decoder, not merely the filename extension.
    metrics sidecarRequiredMissing, malformed, negative, or unparseable metrics fail the candidate.
    Reddit exception: Reddit's public JSON endpoint does not provide views. The fetcher writes score as likes/upvotes and comments, and deliberately omits views. Therefore the rate check is skipped for Reddit; the 500-like floor still applies. Do not fabricate a denominator to make the rate gate pass.

    Duplicate detection uses a 64-bit difference hash (dHash). A candidate within 5 bits of a stored hash is treated as a duplicate. This is perceptual similarity, not robust image identity or copyright detection.

    Data shapes.

    04 — FILE CONTRACTS

    The pipeline uses a paired image and same-stem JSON sidecar. Every field defaults to zero when omitted; views is optional, but a sidecar itself is mandatory.

    Example sidecar

    {
  "views": 50000,
  "likes": 2400,
  "comments": 150,
  "shares": 320
}

    For a Reddit item, views is omitted rather than estimated. The fetcher uses Reddit's score as likes/upvotes; it does not claim that score is a literal like count.

    Manifest shape

    {
  "generated_at": "UTC ISO-8601 timestamp",
  "counts": {
    "passed": 1,
    "rejected": 1,
    "errors": 0
  },
  "passed": [{
    "source": "post.jpg",
    "output": "outbox/post.jpg",
    "width": 1600,
    "height": 1200,
    "caption": "...",
    "engagement_rate": 0.05,
    "sha256": "..."
  }],
  "rejected": [{
    "source": "small.jpg",
    "reasons": ["..."]
  }],
  "errors": []
}

    The engagement_rate field is included when metrics exist; the SHA-256 digest is included for non-dry-run accepted output. This manifest is the publisher's input contract.

    Run it locally.

    05 — OPERATOR NOTES

    Python 3.11 or newer. Runtime dependencies are Pillow and Requests. Pytest and Ruff are in the dev extra. Bluesky's AT Protocol client is an optional extra.

    # Create and activate a virtual environment
python -m venv .venv

# Windows PowerShell
.venv\Scripts\Activate.ps1

# Install the package and developer tools
pip install -e ".[dev]"

# Verify
ruff check .
ruff format --check .
pytest -q

# Fetch Reddit image posts into inbox/
amn fetch --source reddit --query earthporn --limit 10

# Vet, watermark, route and write the manifest
amn run --watermark "@yourhandle"

# Safe inspection: no writes, moves or deletes
amn run --dry-run
    Thresholds are configuration, not CLI flags. Edit the [tool.amn] table in pyproject.toml. A run with no watermark text still works, but the CLI warns when assets pass without a watermark value.

    The fetcher only accepts direct image URLs ending in .jpg, .jpeg, .png or .webp from Reddit's hot listing endpoint. It does not fetch arbitrary Reddit galleries, videos, or general web search results.

    Publishing is opt-in.

    06 — EXTERNAL EFFECTS

    The publishing layer reads passing entries from the manifest. The mock publisher logs to the console. The Bluesky publisher uploads an image and creates a post through the optional atproto dependency.

    # Safe dry publisher
amn publish --platform mock

# Install the optional Bluesky client
pip install -e ".[bluesky]"

# Configure credentials in environment variables
# BLUESKY_HANDLE=yourname.bsky.social
# BLUESKY_APP_PASSWORD=...

amn publish --platform bluesky
    Posting cannot be undone by this pipeline. The scheduled GitHub workflow keeps publishing disabled unless the repository variable AMN_PUBLISH is explicitly set to true. It then expects BLUESKY_HANDLE and BLUESKY_APP_PASSWORD secrets.

    The publisher reports successful post counts but does not persist per-item publish receipts, remote post identifiers, retry state, or idempotency keys. Re-running publish against the same manifest can therefore post the same assets again.

    What it does not do.

    07 — BOUNDARIES

    These are current implementation boundaries, not a roadmap disguised as shipped functionality.

    Not implemented

    No AI vision

    Captioner is a rule-based placeholder based only on likes. It does not inspect image content, generate tags, or call an LLM.

    Not implemented

    No broad source network

    Reddit is the only supported fetcher. Pexels was removed because its assets lacked the engagement metrics required by the gate.

    Not implemented

    No editorial safety review

    No moderation, rights verification, attribution workflow, consent checks, brand-safety model, or human approval queue is present.

    Not implemented

    No publish ledger

    No durable remote post IDs, dedupe across publisher retries, rollback, schedule planner, or per-platform delivery status.

    Operational caveat

    Filesystem is the database

    Inbox, outbox, rejected, hashes and manifest are local files. There is no multi-worker coordination or hosted control plane.

    Workflow caveat

    CI branch mismatch

    The repository's CI workflow currently triggers push events on master, while the repository default branch is main. Pull requests still trigger CI, but main pushes alone do not match that branch filter.

    Security and reliability considerations: Reddit's public endpoint can rate-limit requests; source URLs and image bytes are not independently screened for hostile content; publishing uses long-lived app-password secrets; and a successful local manifest write does not guarantee a successful remote post.
